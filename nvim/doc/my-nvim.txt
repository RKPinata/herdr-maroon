INTRODUCTION                                                        *my-nvim*

my-nvim adds code annotations that you send to herdr agents (pi, claude,
codex). Comment a line or a selection like a code review, list pending
comments, then send them all to any agent in your workspace — with file:line
and git context. Or send nothing but a file:line reference, dropped into a
message you are still typing (|my-nvim.ref_range()|). The plugin is the
nvim half of the herdr workspace plugin; the sidebar itself is provided by the
herdr side.

The sidebar's nvim is a headless daemon, one per herdr tab. It lives as long
as its tab: closing the tab or its workspace stops it immediately (unsaved
buffers in it are discarded), and daemons left over from tabs that did not
survive a herdr restart are reaped when herdr starts.

To list the daemons (tab, workspace/tab names, memory including child
processes such as LSP servers, uptime, state) or stop one by hand without
closing its tab, run the `my-nvim` binary from a shell. The listing ends
with the stop commands, e.g. `stop one: my-nvim daemons stop w26:t2`,
`stop all: my-nvim daemons stop --all`, and `--orphans` when a daemon's
tab is gone:
>sh
  my-nvim daemons                   # --json for machine-readable output
  my-nvim daemons stop w26:t2       # or the key form w26_t2
  my-nvim daemons stop w26:t2 --force
  my-nvim daemons stop --orphans    # daemons whose tab is gone
  my-nvim daemons stop --all [--force]
<
A daemon with unsaved buffers or pending comments is only stopped with
`--force` (orphans never need it). The next toggle starts a fresh nvim.

FEATURES                                                   *my-nvim-features*

An annotated block is drawn as three layers:

- a solid amber rail in the sign column, one cell per line of the block
- a subtle full-width background tint over those same lines
- a callout above the first line naming the comment

Comments are tracked with extmarks, so they follow your edits. They are
ephemeral by design: in-memory only, cleared after a successful send.

A characterwise (|v|) selection inside a line comments just that span: the
agent receives only the selected text, located as `path:12:5-9` (1-indexed
byte columns, inclusive, as in |col()|). A span over several lines sends the
selected text under `path:12-14`. Linewise (|V|) and blockwise selections,
and a |v| selection of one whole line, comment whole lines. The decoration
still marks whole lines.

A pending-comment indicator for your statusline is provided by
|my-nvim.statusline()|.

A reference is the lighter half: just `path:12-20` and a trailing space, with
no comment, no code and no decoration, for naming a location in the middle of
a message you are already typing. The path is shortened against the cwd of the
agent that receives it; a file outside that cwd keeps its absolute path. A
single line collapses to `path:12`. A reference never submits, and never
touches the pending comments.

REQUIREMENTS                                           *my-nvim-requirements*

- Neovim >= 0.10
- herdr >= 0.7.5, running inside a herdr session
- The `herdr` CLI available on PATH (lists agents, sends comments)

INSTALLATION                                           *my-nvim-installation*

Install the herdr plugin for the sidebar (see the plugin README), and the
nvim plugin with your plugin manager. With lazy.nvim:

>lua
  { "ChmaraX/my-nvim", opts = {} }
<

The plugin registers the |my-nvim-commands| command when it loads, so
lazy.nvim can lazy-load it and declare the keymaps in the spec:

>lua
  {
    "ChmaraX/my-nvim",
    cmd = { "Herdr" },
    keys = {
      { "<leader>a", "", desc = "+AI", mode = { "n", "x" } },
      { "<leader>ac", "<CMD>Herdr comment<CR>", desc = "Comment" },
      { "<leader>ac", function() require("my-nvim").comment_selection() end, mode = "x" },
      { "<leader>al", "<CMD>Herdr list<CR>", desc = "List comments" },
      { "<leader>as", "<CMD>Herdr send<CR>", desc = "Send to agent" },
      { "<leader>aS", "<CMD>Herdr submit<CR>", desc = "Submit to agent" },
      { "<leader>ai", "<CMD>Herdr ref<CR>", desc = "Reference lines" },
      { "<leader>ai", ":Herdr ref<CR>", mode = "x" },
    },
    opts = {},
  }
<

The leader-only `+AI` entry creates a which-key group; the `mode = "x"`
entries share one key across normal and visual mode. The comment mapping calls
|my-nvim.comment_selection()| so a characterwise selection keeps its exact
span. The visual reference mapping uses `:` rather than `<CMD>`: the `:` passes
the selection as the `'<,'>` line range, while `<CMD>` would only see the cursor
line.

No plugin manager? It still works in vanilla nvim and in the herdr sidebar
nvim, whose runtimepath the daemon injects: registration happens both from
the runtimepath plugin script and from |my-nvim.setup()|.

CONFIGURATION                                                *my-nvim-config*

Default keymaps are on. They use the `prefix` option (default `<C-k>`)
and never override a map you already set. To bind your own instead, set
`keymaps = false` and use the Lua API (|my-nvim-api|) or the user command
(|my-nvim-commands|).

my-nvim.setup({opts}) ~
  Configure the plugin. Optional — the defaults apply without calling it.

>lua
  require("my-nvim").setup({
    prefix = "<C-k>",         -- prefix for the default keymaps
    keymaps = true,           -- set false to bind your own
    clear_after_send = true,  -- clear comments after a successful send
  })
<

Suggested keymaps: ~

Copy-paste these into your config and adjust to taste — either bind the API
functions directly, or bind through the command:

>lua
  local hn = require("my-nvim")
  vim.keymap.set("n", "<leader>ac", function() hn.comment_line() end)
  vim.keymap.set("x", "<leader>ac", function() hn.comment_selection() end)
  vim.keymap.set("n", "<leader>al", function() hn.list_comments() end)
  vim.keymap.set("n", "<leader>as", "<Cmd>Herdr send<CR>")
  vim.keymap.set("n", "<leader>aS", "<Cmd>Herdr submit<CR>")
  vim.keymap.set("n", "<leader>ai", function() hn.ref_line() end)
  vim.keymap.set("x", "<leader>ai", function() hn.ref_selection() end)
<

Prefer declaring keymaps in your plugin-manager spec? A lazy.nvim example
with a which-key group lives in |my-nvim-installation|.

COMMANDS                                                   *my-nvim-commands*

:Herdr {comment, list, send, submit, ref} ~
  Scoped command for the annotation actions, with subcommand completion.
  The command is registered when the plugin loads; registration is
  idempotent and happens both from the runtimepath plugin script and from
  |my-nvim.setup()|, so it works under lazy.nvim, vanilla nvim, and the
  herdr daemon's injected-runtimepath install alike.

  - `comment`: Add a whole-line comment over the command range. :Herdr
    comment targets the cursor line; :'<,'>Herdr comment targets the visual
    selection's line range; an explicit range like :5,10Herdr comment is
    honored. Use |my-nvim.comment_selection()| for an exact characterwise
    visual span.
  - `list`: Open the comment list (a float). Hover jumps to the comment,
    `⏎` edits, `d` deletes, `q`/<Esc> closes.
  - `send`: Paste all comments into a chosen agent's input (no submit).
  - `submit`: Paste all comments into a chosen agent's input and submit.
  - `ref`: Send a bare `path:line` reference for the command range to a
    chosen agent — no comment, no code, never a submit. :Herdr ref targets
    the cursor line; :'<,'>Herdr ref the visual selection; an explicit
    range like :5,10Herdr ref is honored.

Run :Herdr with no subcommand (or an unknown one) for an error listing
the valid subcommands.

HIGHLIGHTS                                               *my-nvim-highlights*

Set with `default = true`, so colourschemes may override them.

                                               *my-nvim-MyNvimCommentSign*
MyNvimCommentSign ~
  The amber rail in the sign column and the callout corner. Default: bold
  amber. Override to retheme.

                                               *my-nvim-MyNvimCommentText*
MyNvimCommentText ~
  The callout text. Default: amber. Override to retheme.

                                               *my-nvim-MyNvimCommentLine*
MyNvimCommentLine ~
  The background tint under an annotated block. Linked to CursorLine so it
  tracks the active colourscheme; do not override with a fixed color.

API                                                             *my-nvim-api*

The public API is the module returned by `require("my-nvim")`. All
other modules in the plugin are private and may change.

                                                            *my-nvim.setup()*
my-nvim.setup({opts}) ~
  Set plugin options. Optional; the defaults apply without it. Options are
  documented in |my-nvim-config|. Ensures the |my-nvim-commands|
  command is registered.
  Parameters: ~
    {opts} (`table`) Options. See |my-nvim-config|.

                                                    *my-nvim.comment_range()*
my-nvim.comment_range({start_line}, {end_line}) ~
  Add a comment over a 1-indexed, inclusive line range in the current
  buffer. Prompts for the comment text via vim.ui.input.
  Parameters: ~
    {start_line} (`integer`) First line of the range.
    {end_line} (`integer`) Last line of the range (inclusive).

                                                     *my-nvim.comment_line()*
my-nvim.comment_line() ~
  Add a comment on the current line. Equivalent to
  |my-nvim.comment_range()| with the cursor line.

                                                *my-nvim.comment_selection()*
my-nvim.comment_selection() ~
  Add a comment over the current visual selection. A characterwise (|v|)
  selection comments the exact span (multibyte characters and
  'selection' are honored); linewise and blockwise selections comment
  whole lines.

                                                    *my-nvim.list_comments()*
my-nvim.list_comments() ~
  Open the interactive comment list as a floating window. Cursor movement
  previews (jumps the code window to) each comment; `⏎` edits, `d` deletes,
  `q`/<Esc> closes.

                                                     *my-nvim.edit_comment()*
my-nvim.edit_comment({comment}, {on_done}) ~
  Edit a comment's text in place and refresh its decoration. The comment
  is briefly undecorated while editing, then re-decorated with the new text.
  Parameters: ~
    {comment} (`herdr.Comment`) The comment to edit.
    {on_done} (`function|nil`) Optional callback fired when the input closes.

                                                   *my-nvim.delete_comment()*
my-nvim.delete_comment({comment}) ~
  Remove a comment and its decoration.
  Parameters: ~
    {comment} (`herdr.Comment`) The comment to remove.

                                                         *my-nvim.send_all()*
my-nvim.send_all({opts}) ~
  Send all pending comments to a chosen agent (picked via vim.ui.select),
  preceded by the formatted prompt with file:line and git context. Each path
  is shortened against the receiving agent's cwd (a file outside it stays
  absolute), and a single line collapses to `path:12`, the same spelling as
  |my-nvim.ref_range()|. A span inside one line is `path:12:5-9`
  (1-indexed byte columns, inclusive) and sends only the selected text.
  Parameters: ~
    {opts} (`table`) Options:
    - `submit` (`boolean`, default false): when true, auto-submits the text
      into the agent's input instead of just pasting it.

  When |my-nvim.setup()| opts `clear_after_send` is true (the default),
  comments are cleared after a successful send.

                                                        *my-nvim.ref_range()*
my-nvim.ref_range({start_line}, {end_line}) ~
  Send a bare `path:line` reference for a 1-indexed, inclusive line range to
  an agent, with a trailing space and nothing else: no comment, no code, no
  git context. A single-line range collapses to `path:12`. The path is
  shortened against the cwd of the agent that receives it; a file outside
  that cwd keeps its absolute path. Never submits, and never touches pending
  comments. A buffer with no file name is refused with a warning; a buffer
  with unsaved changes warns (the agent reads the file on disk) but still
  sends.
  Parameters: ~
    {start_line} (`integer`) First line of the range.
    {end_line} (`integer`) Last line of the range (inclusive).

                                                         *my-nvim.ref_line()*
my-nvim.ref_line() ~
  Reference the current line. Equivalent to |my-nvim.ref_range()| with the
  cursor line.

                                                    *my-nvim.ref_selection()*
my-nvim.ref_selection() ~
  Reference the current visual selection. Equivalent to
  |my-nvim.ref_range()| over the visual marks.

                                                       *my-nvim.statusline()*
my-nvim.statusline() ~
  Statusline indicator for pending comments.
  Return: ~
    `string` `"● N"` when N comments are pending, or `""` when none.

TROUBLESHOOTING                                     *my-nvim-troubleshooting*

Run the health checks first:

>vim
  :checkhealth my-nvim
<

Common Issues: ~

Issue: :Herdr is not recognized ~
- For lazy-loaded installs, the command is registered when the plugin loads
  (first keypress, or the first :Herdr with `cmd = { "Herdr" }`).
- If a plugin manager resets 'runtimepath' and the plugin is not installed
  in your nvim config, :Herdr exists only in the herdr sidebar nvim
  (whose runtimepath the daemon injects).

Issue: The sidebar daemon does not start ~
- Make sure `sidebar.nvim_bin` points at a working nvim >= 0.10 (see the
  plugin README for the herdr-side config).
- If the sidebar pane opens and immediately disappears, `nvim` was not found
  on the PATH herdr gave the pane. herdr passes on the PATH of the herdr
  server process, which lacks your Homebrew prefix when the server was
  started from a systemd unit or over SSH. Set an absolute path:
  `nvim_bin = "/home/linuxbrew/.linuxbrew/bin/nvim"`.
